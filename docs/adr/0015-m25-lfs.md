# ADR 0015: M25 LFS — Log-Structured File System (OSEP Ch. 43)

## Status

Accepted

## Date

2026-09-21

## Context

Part III Persistence has M11 (raw I/O), M12 (vsfs + journaling), M21 (FFS placement), and M24 (RAID). The persistence thread still misses the most influential modern concept: the log-structured file system. OSEP Ch. 43 is the canonical chapter — and the most-cited reference in modern copy-on-write filesystems (WAFL, ZFS, btrfs, flash-based SSDs).

Without LFS, the lab can't show how to make all writes sequential or how to garbage-collect old versions of files. The "and the disk gets fragmented" half of the persistence story is missing.

## Decision

We add `MiniScheduler.Lfs` with segments + imap + checkpoint region + segment cleaner.

### 1. Three pieces: segment buffer + imap + CR

OSEP walks through five pieces; we implement the three that are most visible in the trace:

- **Segment** (§43.2): an in-memory buffer that accumulates `LfsBlock`s (data, inode, imap chunk) until full, then flushes to disk.
- **Inode map (imap)** (§43.5): `inodeNum → diskAddress` indirection. Pieces of the imap ride along in each segment flush so they don't require a separate seek.
- **Checkpoint region (CR)** (§43.6): fixed slot at segment 0 that points to the latest imap piece + log head.

The fourth piece — the segment summary block (§43.10) that records `(inode, offset)` per block — is what enables the cleaner to tell live from dead.

### 2. In-memory disks, no device-level latency

Each disk is `LfsBlock[Segments, BlocksPerSegment]`. We model the *layout* and *garbage* properties of LFS, not seek time. The segment cleaner is the headline observable.

### 3. Block liveness via segment summary

A block at `(segment, slot)` is live if the segment summary's `(inodeNum, offset)` matches what the current inode (via the imap) says at that offset. Otherwise it's dead — eligible for cleaning. This is OSEP §43.10's pseudocode:

```
(N, T) = SegmentSummary[A];
inode = Read(imap[N]);
if (inode[T] == A)  // block D is alive
else                // block D is garbage
```

### 4. "Coldest segment first" cleaning policy

OSEP §43.11's hot/cold segregation is interesting but adds two counters (age + util) and a sorting cost. We implement the simplest defensible policy: pick the segment with the fewest live blocks first. The route accepts a custom policy name for future extension.

### 5. Single CR slot

OSEP §43.12 keeps two CRs and writes to them alternately for atomic updates. We use a single CR slot — the simulator doesn't crash unless explicitly told, so the second CR is unnecessary noise.

### 6. Route exposes three scenarios

`/lfs/run?scenario=create|rewrite|clean`:

- `create` — create N files with M blocks each; observe segments, imap, CR, segment summaries.
- `rewrite` — rewrite some of the files; observe the dead block count and which segments are most fragmented.
- `clean` — run the segment cleaner; observe live-block compaction + freed segments.

## Consequences

### Positive

- **Closes Ch. 43** — the canonical LFS chapter is demonstrated end-to-end.
- **Reuses M21's "coldest first" pattern** for the cleaner policy; future work could swap in OSEP §43.11's hot/cold segregation.
- **Composes with M24** — LFS sits above RAID in the stack; the lab's persistence story now has the layer that uses RAID's sequential-write bandwidth (OSEP §43.1: "RAID-aware").
- **No new dependencies** — `Dictionary<int, int>` + arrays.

### Negative

- **In-memory disks only** — no real I/O latency, no real failure timing.
- **Single CR slot** — real LFS uses two (§43.12). The single-slot model is sufficient for the simulator's no-crash default.
- **No hot/cold segregation** — we use a simpler "coldest first" policy.
- **No multi-piece imap** — one imap piece per flush; the CR points to the latest one.

## Verification

- Build clean.
- Existing tests still pass (no test changes).
- New tests cover: write/read round-trip via imap; CR points to latest imap piece; segment summary records `(inode, offset)` per block; rewrite makes old block dead; cleaner compacts live blocks + frees old segment.
- Smoke: `/lfs/run?scenario=create` shows the segment grid + CR + imap after N file creations.
- Smoke: `/lfs/run?scenario=rewrite` shows the dead-block count after rewriting some files.
- Smoke: `/lfs/run?scenario=clean` shows the compaction + freed segments.
